## 1. 项目背景与目标

### 1.1 背景

AI 应用开发学习者在学习过程中普遍存在三个问题：

1. **资料分散**：课程讲义、代码示例、笔记分布在不同目录和格式中，复习时难以定位到某个具体知识点。
2. **缺少反馈**：看完课程后没有练习和检验环节，无法判断自己是否真正掌握。
3. **没有复习节奏**：错过的知识点不会被重新安排，学过即忘。

现有的“上传资料 + 聊天问答”类工具只能解决第一个问题的一半，它们能回答问题，但不产生练习、不记录错题、不安排复习，用户无法通过工具看到自己的变化。

### 1.2 项目目标

构建一个面向个人学习者的学习闭环产品：**导入资料 → 带引用问答 → 生成练习 → 提交答案 → 分析薄弱点 → 安排复习**。

### 1.3 成功标准

项目按“产品是否真的帮到用户”衡量，而不是按用了多少 AI 技术衡量。第一版上线后需满足：

| 编号 | 成功标准 | 目标值 |
| --- | --- | --- |
| SC-01 | 新用户从打开页面到完成第一次提问 | ≤ 3 分钟 |
| SC-02 | 知识问答的答案带可点击引用，且引用能支撑结论 | ≥ 90% 的回答包含有效引用 |
| SC-03 | 资料中没有答案时，系统明确拒答而不是编造 | 拒答准确率 ≥ 90%（以评测集为准） |
| SC-04 | 章节练习题目与所选章节相关 | 人工抽检相关性 ≥ 90% |
| SC-05 | 用户次日再次使用 | 试用用户次日回访率 ≥ 40% |
| SC-06 | 完成一次章节复习所需时间 | 相比手工复习减少 ≥ 50% |

> 所有指标必须来自真实测量。简历和项目文档中只填写实测结果，不虚构用户量与提升比例。

### 1.4 项目性质

求职作品集项目 + 真实效率工具。要求：可部署、可演示、有真实用户、有评测数据。

## 2. 术语定义

| 术语 | 含义 |
| --- | --- |
| 学习空间（Workspace） | 用户隔离数据的最小单位，包含该用户的所有课程资料、会话、练习和复习任务 |
| 课程（Course） | 学习空间下按主题组织的一组资料，对应用户正在学的一门课或一个章节 |
| 父块 / 子块 | 文档切分的两级结构。子块用于精确检索，父块用于提供完整上下文 |
| 引用（Citation） | 回答中指向原文片段的结构化来源信息，包含文件名、标题路径和页码 |
| 拒答 | 检索结果低于阈值时，系统明确说明“资料中没有相关内容”，不调用模型编造 |
| 薄弱知识点 | 依据错题记录统计出的、用户掌握程度较低的知识点 |
| RRF | Reciprocal Rank Fusion，用于融合向量检索与关键词检索的排名结果 |

## 3. 用户与角色

第一版只有一类真实用户，但权限模型按多角色设计，便于后续扩展。

| 角色 | 描述 | 主要诉求 | 权限 |
| --- | --- | --- | --- |
| 学习者（owner） | 正在学习 AI 应用开发的个人，本产品的主要用户 | 快速理解资料、检验掌握程度、按计划复习 | 管理自己的学习空间、资料、练习和复习任务 |
| 学习同伴（member） | 被邀请进入同一学习空间的同学 | 共享课程资料与练习 | 只读资料、可问答和答题，不能删除资料 |
| 运营/评估者（内部） | 项目作者本人 | 查看检索质量、成本与失败率 | 访问评估与统计接口，不访问用户正文数据 |

### 3.1 典型用户画像

- 5～6 年经验的前端开发者，正在脱产参加 AI 应用开发培训；
- 手上有大量课程讲义（Markdown、PDF、DOCX）和代码示例；
- 每天有固定学习时间，但缺少检验和复习环节；
- 主要设备是 Windows 笔记本，也会用手机碎片时间复习。

### 4.1 端到端主流程

```text
注册 / 登录
  -> 进入个人学习空间
  -> 上传课程资料（Markdown / PDF / DOCX）
  -> 等待异步解析和向量化完成
  -> 针对某节课提问，获得带引用的流式回答
  -> 点击引用查看原文片段
  -> 点击“生成练习”，得到 5 道题
  -> 提交答案，查看解析和错因
  -> 系统记录错题并生成薄弱知识点
  -> 首页出现待复习任务
  -> 按复习任务回到对应章节
```

## 5. 功能需求

优先级定义：**P0** 第一版必须交付；**P1** 第一版尽量交付；**P2** 后续版本。

### 5.1 账号与会话（FR-AUTH）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-AUTH-01 | 用户可使用邮箱和密码注册，密码长度不少于 8 位 | P0 |
| FR-AUTH-02 | 密码必须以 Argon2id 或 bcrypt 哈希后存储，任何日志和接口响应不得出现明文密码或哈希 | P0 |
| FR-AUTH-03 | 同一邮箱重复注册必须被拒绝，返回稳定的错误码 | P0 |
| FR-AUTH-04 | 用户可使用邮箱和密码登录，登录失败时不得泄露账号是否存在 | P0 |
| FR-AUTH-05 | 登录成功后在 HttpOnly Cookie 中写入会话令牌，Cookie 设置 `HttpOnly`、`SameSite=Lax`，生产环境启用 `Secure` | P0 |
| FR-AUTH-06 | 会话有效期默认 7 天，过期后受保护接口返回 401 | P0 |
| FR-AUTH-07 | 用户可退出登录，退出后旧会话令牌立即失效，不能继续访问受保护接口 | P0 |
| FR-AUTH-08 | 注册成功后自动为用户创建一个个人学习空间，并把用户写为 owner | P0 |
| FR-AUTH-09 | 提供当前登录用户信息查询接口，未登录返回 401 | P0 |
| FR-AUTH-10 | 会话令牌在数据库中只保存哈希值，不保存原文 | P0 |
| FR-AUTH-11 | 支持修改密码，修改后吊销其他设备上的会话 | P1 |
| FR-AUTH-12 | 同一用户并发会话数量上限可配置 | P2 |

### 5.2 学习空间（FR-WS）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-WS-01 | 用户可查询自己当前的学习空间信息 | P0 |
| FR-WS-02 | 用户可重命名自己的学习空间 | P0 |
| FR-WS-03 | **所有**业务查询必须带 `workspace_id` 或 `user_id` 条件，非成员访问任何空间资源必须返回 403 或 404 | P0 |
| FR-WS-04 | 权限校验集中在服务层完成，不允许只在路由层根据 URL 中的 id 直接查询 | P0 |
| FR-WS-05 | 学习空间可通过邀请码添加 member 成员 | P2 |

### 5.3 课程资料管理（FR-DOC）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-DOC-01 | 用户可上传资料，第一版支持 Markdown、TXT、PDF、DOCX 四种格式 | P0 |
| FR-DOC-02 | 上传前校验文件扩展名、MIME 类型和大小，单文件上限默认 20 MB，超限返回明确错误码 | P0 |
| FR-DOC-03 | 上传时计算文件 SHA-256；同一学习空间内相同哈希的文件重复上传时，复用已有解析结果，不重复生成向量 | P0 |
| FR-DOC-04 | 原始文件保存到对象存储或本地存储，数据库中保存可追溯的存储路径 | P0 |
| FR-DOC-05 | 文档解析与向量化以异步任务执行，接口必须立即返回，不能阻塞请求 | P0 |
| FR-DOC-06 | 文档状态至少包含 `pending`、`processing`、`ready`、`failed` 四种，用户可查询状态 | P0 |
| FR-DOC-07 | 解析失败时记录错误信息，用户可看到失败原因并发起重试 | P0 |
| FR-DOC-08 | 用户可查看学习空间内的资料列表，包含文件名、类型、状态、大小和上传时间 | P0 |
| FR-DOC-09 | 用户可删除资料，删除时同步清理该文档的所有分块和向量 | P0 |
| FR-DOC-10 | 用户可预览或下载已上传的原始文件 | P1 |
| FR-DOC-11 | 支持 Markdown 文档的标题层级解析，用于生成父子块 | P0 |
| FR-DOC-12 | PDF 解析保留页码信息，DOCX 解析保留标题样式 | P0 |
| FR-DOC-13 | 支持文档版本更新，更新后旧版本分块失效 | P2 |
| FR-DOC-14 | 第二版支持 HTML、CSV、JSON | P2 |

### 5.4 文档切分与入库（FR-ING）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-ING-01 | 采用父子块两级切分：父块 500～800 中文字符，子块 150～300 中文字符，重叠 30～50 字符 | P0 |
| FR-ING-02 | 父块与子块之间必须建立关联，检索命中子块后可恢复父块上下文 | P0 |
| FR-ING-03 | 每个分块必须保存元数据：`document_id`、文件名、标题路径、页码、分块序号 | P0 |
| FR-ING-04 | 分块文本必须清洗：去除多余空白、页眉页脚、重复换行，但不得破坏代码块和表格结构 | P0 |
| FR-ING-05 | 为每个子块生成 Embedding 并写入向量库 | P0 |
| FR-ING-06 | 同时建立关键词检索索引（第一版使用 PostgreSQL 全文检索） | P0 |
| FR-ING-07 | 入库过程必须幂等：任务重试不得产生重复分块 | P0 |
| FR-ING-08 | 切分参数必须可通过配置调整，不得硬编码在业务逻辑中 | P0 |
| FR-ING-09 | 记录每个文档的分块数量，便于排查切分异常 | P1 |

### 5.5 知识库问答（FR-CHAT）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-CHAT-01 | 用户可针对指定课程或资料范围发起提问 | P0 |
| FR-CHAT-02 | 问答链路为：意图判断 → 查询改写 → 向量检索 → 关键词检索 → RRF 融合 → 重排 → 阈值判断 → 上下文构建 → 生成 | P0 |
| FR-CHAT-03 | 检索参数可配置，初始值：向量 Top 20、关键词 Top 20、RRF 合并 Top 10、重排 Top 5、最终入模 Top 3~5 | P0 |
| FR-CHAT-04 | 回答必须以 SSE 流式返回，事件类型包含 `start`、`token`、`citation`、`error`、`end` | P0 |
| FR-CHAT-05 | 回答必须附带结构化引用，包含文件名、标题路径、页码和分块 id | P0 |
| FR-CHAT-06 | 前端可点击引用展开原文片段 | P0 |
| FR-CHAT-07 | 当最高检索分数低于阈值时，系统必须拒绝回答并说明资料中没有相关内容 | P0 |
| FR-CHAT-08 | 系统提示词必须约束：只依据提供资料回答、资料不足时明确说明、不补充无来源结论、先结论后解释 | P0 |
| FR-CHAT-09 | 会话与消息必须持久化，用户可查看历史会话并继续追问 | P0 |
| FR-CHAT-10 | 多轮追问时须携带必要的历史上下文，使指代可解析 | P1 |
| FR-CHAT-11 | 用户可对单条回答重新生成 | P1 |
| FR-CHAT-12 | 用户可中途停止生成，已生成内容保留 | P1 |
| FR-CHAT-13 | 回答中提供“加入错题本”和“生成练习”操作入口 | P1 |
| FR-CHAT-14 | 记录每条回答的耗时、token 用量和引用数量 | P0 |
| FR-CHAT-15 | 意图识别需区分知识问答、练习生成、错题解析、学习计划和普通寒暄，仅知识问答进入 RAG 链路 | P1 |
| FR-CHAT-16 | 知识库中无法回答时，可选择性接入联网搜索，但必须在回答中区分知识库答案与外部来源 | P2 |

### 6.2 安全（NFR-SEC）

| 编号 | 需求 |
| --- | --- |
| NFR-SEC-01 | 所有资源访问必须经过 workspace 成员校验，禁止仅凭前端传入 id 查询数据 |
| NFR-SEC-02 | 会话令牌存放于 HttpOnly Cookie，不使用 localStorage 保存长期凭证 |
| NFR-SEC-03 | 所有写操作要求携带会话并做 CSRF 防护（`SameSite` + 自定义请求头校验） |
| NFR-SEC-04 | 上传文件做类型白名单与内容校验，拒绝可执行文件和超限文件 |
| NFR-SEC-05 | 文档内容作为不可信输入，提示词需防范文档中注入的指令 |
| NFR-SEC-06 | 禁止使用不安全的反序列化（如 `allow_dangerous_deserialization=True`），除非数据来源完全可信 |
| NFR-SEC-07 | 密钥与配置通过环境变量注入，仓库只提交 `.env.example`，不得提交真实密钥 |
| NFR-SEC-08 | 接口按用户限流，防止模型调用被滥用 |
| NFR-SEC-09 | 用户可删除自己的账号及其全部数据 |

### 6.3 可靠性与一致性（NFR-REL）

| 编号 | 需求 |
| --- | --- |
| NFR-REL-01 | 文档入库、答题记录写入等关键流程必须幂等，可安全重试 |
| NFR-REL-02 | 异步任务失败必须记录原因并支持重试，不能静默丢失 |
| NFR-REL-03 | 模型调用失败或超时时，接口返回明确错误并允许用户重试，不得返回半截内容当作成功 |
| NFR-REL-04 | SSE 连接中断时前端能感知并提示，服务端不保留脏状态 |

## 9. 验收标准

### 9.1 资料导入（对应 FR-DOC / FR-ING）

- **Given** 用户已登录并进入自己的学习空间，**When** 上传一份 10 MB 的 PDF，**Then** 接口 2 秒内返回，文档状态为 `pending`，随后在合理时间内变为 `ready`。
- **Given** 文档已为 `ready`，**When** 上传完全相同内容的文件，**Then** 系统识别为同一文件，不产生重复分块，分块总数不变。
- **Given** 上传了一个损坏的 PDF，**When** 解析失败，**Then** 文档状态为 `failed`，错误信息可见，用户可点击重试。
- **Given** 用户 A 的文档 id，**When** 用户 B 请求该文档详情，**Then** 返回 404 或 403，不返回任何内容。

### 9.2 知识问答（对应 FR-CHAT）

- **Given** 资料已入库，**When** 用户就其中某个概念提问，**Then** 回答流式输出，且包含至少一条引用，引用可点击展开原文。
- **Given** 用户询问资料中完全不涉及的内容，**When** 检索分数低于阈值，**Then** 系统明确说明资料中没有相关内容，不生成推测性回答。
- **Given** 用户正在等待回答，**When** 点击停止生成，**Then** 流式输出立即停止，已生成内容保留在会话中。
- **Given** 一次问答完成，**When** 查看消息记录，**Then** 能查到该次请求的耗时与 token 用量。

### 9.3 练习与复习（对应 FR-QUIZ / FR-REV）

- **Given** 用户选中某一章节，**When** 点击生成练习，**Then** 得到 5 道通过校验的题目，每题带知识点和来源。
- **Given** 生成的题目中有选项数量异常或答案不存在的情况，**When** 展示给用户前，**Then** 该题被丢弃或重新生成。
- **Given** 用户答错一道题，**When** 查看错题本，**Then** 该题出现在错题本中并关联到对应知识点。
- **Given** 用户首次答错某知识点，**When** 系统生成复习任务，**Then** 复习日期为 1 天后，且该结果可被单元测试稳定复现。

### 9.4 工程基础（对应 NFR）

- **Given** 一台全新开发机，**When** 按 README 执行启动步骤，**Then** 能启动数据库、后端和前端，`/health` 返回 200。
- **Given** 空数据库，**When** 执行 `alembic upgrade head`，**Then** 全部表创建成功，可重复执行不报错。
- **Given** 未登录用户，**When** 访问受保护接口或前端受保护路由，**Then** 接口返回 401，前端跳转到登录页。
- **Given** 认证和 workspace 相关代码，**When** 执行测试命令，**Then** 核心用例全部通过。

## 12. 假设、依赖与风险

### 12.1 假设

1. 用户具备基本的计算机操作能力，能理解上传资料和答题的流程；
2. 用户的学习资料以电子文档形式存在，且允许上传到个人学习空间；
3. 模型服务通过 OpenAI 兼容接口访问，可替换供应商；
4. 第一版部署规模为数十名用户量级，模块化单体足够。

### 12.2 依赖

| 依赖 | 影响 |
| --- | --- |
| 可用的 LLM 与 Embedding 接口 | 阻塞 RAG 与练习生成 |
| PostgreSQL + pgvector | 阻塞向量检索 |
| Docker 环境 | 阻塞本地与线上部署验证 |
| 真实课程资料与真实问题 | 阻塞评测集建设 |

### 12.3 风险

| 编号 | 风险 | 影响 | 应对 |
| --- | --- | --- | --- |
| R-01 | 过早接入 Milvus、Elasticsearch、Celery、MinIO，第一周变成环境排错周 | 进度失控 | 第一版只用 PostgreSQL + pgvector，Redis 仅预留 |
| R-02 | 过早设计完整业务库表 | 返工 | 第 1 周只建认证与空间相关表 |
| R-03 | 认证方案中途更改 | 大量返工 | 第一版固定 HttpOnly Cookie Session，不中途换 JWT |
| R-04 | 前端状态双份存储导致不同步 | 难排查的 UI 缺陷 | 服务端状态交给 TanStack Query |
| R-05 | 模型幻觉导致用户信任下降 | 产品价值受损 | 强制引用、低分拒答、评测集验证 Faithfulness |
| R-06 | 生成题目质量不稳定 | 练习环节失效 | 结构化输出 + 程序化校验 + 抽检 |
| R-07 | 评测集问题数量不足 | 结论不可信 | 第 6 周前累积不少于 50 条真实问题 |
| R-08 | 只做 API 不做完整演示流程 | 无法演示与面试 | 每周必须从浏览器完成端到端流程 |
| R-09 | 忽视数据隔离 | 安全事故 | 从第 1 天起按 workspace 成员关系授权 |
| R-10 | 用户量不足导致产品指标无数据 | 简历表述缺乏支撑 | 提前联系培训班同学，保证 5～10 名试用者 |
